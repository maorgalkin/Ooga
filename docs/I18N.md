# Languages (English and Hebrew)

Ooga is being translated into Hebrew. Until every screen is done, Hebrew is hidden: the language switch and Hebrew text appear only in builds with `VITE_ENABLE_HEBREW=1` (put it in `.env.local` to work on it). Production leaves it unset and stays English, whatever anyone saved.

## How it fits together

| Piece | What it does |
|---|---|
| `src/i18n/index.ts` | Sets up i18next with both languages; `applyLanguage()` switches language and page direction (`<html lang dir>`) and remembers the choice in this browser |
| `src/i18n/locales/en.json`, `he.json` | The text, nested by feature (`language.settings.title`) |
| `src/services/preferencesService.ts` | Reads and saves `language` and `address_as` in the auth user's metadata, next to their name, so they follow the account to every device |
| `src/i18n/LanguageSync.tsx` | Applies the signed-in account's language; on first sign-in, carries over a language picked while signed out |
| `src/hooks/useT.ts` | `t` that picks the reader's form of address (below) |
| `src/components/settings/LanguageSettings.tsx` | The Language card in Budget settings |
| The switch in `PublicLayout` | Lets signed-out visitors change language on About and the Guide |

Which language shows: the account's choice, else this browser's last choice, else English.

## Writing translatable text

- Use `useT()` in anything a signed-in person sees, `useTranslation().t` on signed-out pages. Keys are English-free identifiers grouped by feature; add every key to both files (a test fails if `he.json` is missing one).
- Money goes through `formatCurrency*` and dates through `getUserLocale()`: both follow the language (`he-IL` on Hebrew screens). A hard-coded `'en-US'` stays English on Hebrew screens.
- Text from banks is already Hebrew: never translate it; render it with `dir="auto"`.

## Addressing the reader in Hebrew

Hebrew verbs and adjectives change with the reader's gender. People can choose how Ooga addresses them (Budget settings → Language → "How Hebrew addresses you"): neutral, female or male. It's stored as `address_as` in their account and is optional.

- **Every key has a neutral version.** Write it with verbal nouns and impersonal forms (`הוספת הוצאה`, `שמירה`, `כדאי לנסות שוב`). It's what signed-out pages, the guide, household-wide text and anyone who chose neutral see.
- **Add gendered variants only where a sentence reads better gendered:** `key_female` and `key_male` next to `key`, in `he.json` only. `useT()` picks the variant for the reader's choice and falls back to the neutral key when there's none.
- Buttons stay verbal nouns (`שמירה`, not `שמור`/`שמרי`), as Israeli apps usually do.

## Right to left

`applyLanguage('he')` sets `dir="rtl"` on `<html>`, so the browser flips text and flex direction. Classes with a side in them don't flip: use the logical versions (`ms-`/`me-`, `ps-`/`pe-`, `start-`/`end-`, `text-start`, `rounded-s`), add `rtl:` variants where needed (`rtl:rotate-180` on a "next" arrow), and check swipes and slide animations, which move by `x`.
